## Checks and behaviour (implementer 2, built 28 Oct)

- H1 (K2.1 composition) | Every row needs INCI (European) / IUPAC, Function, an Additive answer and a concentration range (min and max, 0–100 %, min ≤ max). A blank concentration is stored as empty (never 0); a legacy 0–0 row counts as missing. Rows are saved as typed (autosave of partial input); the completeness check and the final release block, one item per problem, named "Component N: …", and the item jumps to the row | The matrix makes the composition mandatory per component; partial input must still autosave. Both containers use the same check (the portal's confirmation runs the domain's completeness check).
- M1 (CAS) | Format and check digit checked when filled; a wrong one is shown at once under the input and blocks completeness. A CAS number stays optional | A wrong CAS number is a typo the supplier can fix; the matrix does not make CAS mandatory for every component.
- M2 (EC) | The EC field also takes a REACH registration number 01-0123456789-01-0000 (format only, no check digit exists); label "EC number (EINECS/ELINCS/NLP) or REACH registration no."; tables read "EC / REACH no." | The matrix allows either in one field. **tell BDF** (one field for both, no separate REACH column)
- M3 (FLD-2.1-102 Natural origin index) | 0–1 with at most 2 decimals; more decimals block | The matrix's format "max. 2 decimals".
- M14 (FLD-A4-101 MOAH) | 0 or more | A concentration can't be negative.
- M15 (FLD-A4-103 kinematic viscosity) | Greater than 0 | A viscosity of 0 or less is not a measured value.
- M8 (FLD-A1-104 Content [%] in raw material) | A soft warning, never a blocker. Of the two decided options, we chose the union of the components' ranges in K2.1, [lowest minimum, highest maximum]. The warning shows only when the value lies below or above it, and it names the range: "This value lies outside the concentration range of the components in K2.1 (0.1–99 %). Please check it." A row with an invalid range (min above max, outside 0–100 %) is left out, because it has its own blocker. The supplier sees the warning under the field, the reviewers next to the answer (fixer, 28 Oct; this replaces the first build's "inside one component's range") | The union warns only on a value no component's range can explain. The sum of the ranges would warn on almost every single-feedstock material, and a per-row check warned between two rows' ranges, which the decision did not ask for. **tell BDF**
- M9 (FLD-A2-101 pre-fill) | Pre-filled when Annex 2 opens (a metadata answer, a Part 2 origin change, or a department adding Annex 2) while the field is empty and was never answered or justified; a value the supplier cleared is not filled again. In the prototype the pre-fill reads "Pre-filled"; in the live portal it is saved together with the metadata answer, so it carries the saving contact's name | One mechanism in both containers; the portal has no "system" writer, and the save that opened Annex 2 is the contact's.
- L4 (K2.1 INCI column) | Label "INCI (European) / IUPAC" with the guidance "The INCI name. If there is none: the chemical name (IUPAC). For colorants, also the Colour Index number."; tables read "INCI / IUPAC" | The matrix's wording; no separate Colour Index column.
- L5 (K2.1 Additive) | An explicit Yes/No per row with no default, required; no follow-up fields; a legacy "false" (the old checkbox) reads as No, an unanswered row shows "—" | The matrix asks it per component; a default of No would answer it for the supplier.
- D6 (origin consistency, choice) | Built as a completeness and release **blocker**, both ways: a row whose origin is not an SF-01 answer ("Component N: its origin … is not one of the origins you selected in the metadata questions"), and an SF-01 answer no row uses ("You selected the origin …, but no component has it"). Checked only once SF-01 is answered. The K2.1 editor shows the row's mismatch under Origin at once and keeps the stale option visible so it can be changed | SF-01 drives the annexes, so a mismatch means missing or superfluous annexes; a warning would let a wrong scope pass. **tell BDF**
- D10 (no "Cannot provide" on FLD-A1-201, FLD-A1-204, FLD-A4-102) | The button and the justification box are not offered; a justification stored before 28 Oct stays in the data but no longer counts, so such a case is blocked until the question is answered | A justification would skip the Yes → upload / No → reason chain.
