### 1.7 Platform facts verified live (evidence in `SPIKES.md` "Night tests", `postgen/*-result.json`, D32–D37)

**Steps and API key**
1. Parallel branches fork only for flagged branches. All-unflagged skips the block cleanly. Simultaneous submits are fine, and the join waits for every branch.
2. The **API key acts as its user**:
   - it can submit, reject and withdraw a step whose role includes that user;
   - it **cannot update fields after Start** (050313, even for Editable fields);
   - the **admin route** `PUT /process/2/{acc}/admin/{proc}/{item}` writes any field;
   - **Mandatory is not enforced** on a key submit;
   - **field-level Required at Start is enforced** (portal finding).
3. **Send-back over the API key returns 500 in every form**, even with `IsSendbackEnabled` on. A real-user send-back (native or SDK) is still **[unverified]**.
4. Reject and withdraw don't fire ItemCompleted.

**Concurrency and drafts**
5. **No write locking:** simultaneous writes within ~0.1 s lose updates on every route (child rows: 5/5 lost). A stale `_doc_version` is accepted.
6. **Per-user Form draft:** two creates at once by the same user collide.

**Child rows and formulas**
7. **A Form create replaces client child-row ids.** A **modify that names an unknown row id ADDS a row** (a silent duplicate).
8. Child formula columns and header formulas compute server-side. **A never-written Number reads blank (not 0)**, so `Hold = "Yes"` on a new case.

**Lists and the SDK**
9. **getParticipatedItems errors** in the app as well as the portal (platform-wide).
10. SDK list envelopes:
    - My items: `{Columns,Data}`, sparse rows that carry the step and `_activity_instance_id`;
    - My tasks: `{_id,Columns,Sort,Filter,Data}`; the **activity filter works live**;
    - admin list: 30/125 fields and no `_activity_instance_id`.
11. AppRoles carry the role names and ids.

**Access and UI**
12. Page-session `fetch` writes get **403** (anti-forgery). Only the SDK or the native UI writes as the user.
13. A no-pages app's tasks don't appear in the home queue; users work in the custom UI.
14. The Claude in Chrome extension **can't click or type inside the cross-origin custom-UI frame**. Real-user UI tests need Thomas.
15. Portal finding: SDK `uploadFile` works live (portal PARITY.md).

**Account**
16. The dev account banner says **"trial ends in 5 days"** (seen 8 Oct).

## 2. What must change in the app for the 9–14 Oct decisions

Sources: the client call (D-1…D-3, R-1, R-2, AS answers), `prototype/FINAL-APP-SPEC.md` (§1–§8.5) and `DEMO-GUIDE.md`.
- **Mechanics:** App Builder 1.0.0 can't edit an app after generate. Changes go through REST (old-engine patch verbs or grafts), or through a regenerate under new flow names.
- **What REST allows:**
  - published processes accept clean grafts, and steps can be removed by a re-PUT [verified, portal];
  - fields can't be deleted from a published process [manual];
  - Live process flows can be archived and then deleted [manual].
