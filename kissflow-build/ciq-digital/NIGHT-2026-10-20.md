## 9. 20 Oct evening: supplier contacts (Thomas's report)

### Symptom 1: adding a contact to a new supplier "doesn't add it"
**Cause (proven):** a contact created in the app got the id `u-s1-1`. The mapper reads a contact without a portal user back as `contact:<key>`, so the domain's next new contact got `u-s1-1` again. It was saved with the SAME key, and on reload the rows merged into one. The write check then matched the first contact's row and reported "Not saved".

**Live evidence:** supplier "12343Thomas Supplier" (s1) has 3 rows, all with key `u-s1-1`.

**Fix:** a contact the app created keeps its key as its id (`map/suppliersMap.ts`). `u-<supplier>-<n>` ids are never treated as Kissflow or portal users (`write/encode.ts`).

### Symptom 1b: a new supplier's contact row was duplicated on create
**Cause:** the first read-back showed no child rows yet, so the row was sent again.

**Fix:** wait 1.5 s and read again before re-sending (`write/actions.ts` `formCreated`).

### 9b. The real cause of "contacts don't add / can't edit an e-mail" (found in Thomas's Chrome)

**Seen live:** the Suppliers page showed "0 active" contacts for every supplier, and the dev supplier said "No contact yet", although Kissflow holds its active contact.

**Cause (proven with the key):** Kissflow's form **list** (`POST /form/…/list`, the SDK's getItems) returns rows **without their child tables**. Only a full item read returns them:
- a supplier's list row has no `Table::Contacts`, while its GET has 3 rows;
- an RMES list row has no `Safety_Criteria` / `Safety_Findings`, while its GET has 5 + 2.

The app read these forms by list only, so live it had no contacts (no edit possible; a new contact vanished on reload) and no RMES criteria. The fake Kissflow returned child rows in lists, so the tests never saw it.

**Fix:**
- `load.ts` reads Supplier, RMES Safety and RMES Regulatory item by item after the list; a failed full read keeps the row with a warning.
- The fake client and the harness host now leave child tables out of lists, as live does.
- 3 new load tests, proven to fail without the fix.

**Gate and deploy:** 978/978 unit tests, harness 27/27 (259 checks). Deployed `ciq-app-ui-13fbb5506b.zip`, read back Live.

**Live check in Thomas's Chrome:** the Suppliers list shows 1 / 1 / 1 / 3 active contacts. The dev supplier's page lists its contact with Edit and Deactivate.
